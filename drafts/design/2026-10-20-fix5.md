## 1. 히어로 "UNSILENT" 외곽선 글자

**원인**
- `.word`가 `bottom:-.3em`, `font-size:min(19vw,32svh)`라서 글자 대부분이 하단 실적 띠(`.credits`, 데스크톱 높이 74px) 뒤에 깔린다. 1440×900에서 글자 위 끝은 723px이고 띠는 826px부터 시작한다. 그래서 위쪽 100px 정도만 보인다.
- 19vw에서는 글자 폭이 6.4em, 1440 기준 1751px라 화면보다 넓다. 오른쪽 "ENT"는 원래 잘려 있었다.
- 모바일(≤860)에서는 `.credits`가 흐름 안으로 들어오고 `.word{bottom:0}`이라 글자 전체가 띠 뒤에 가려 하나도 안 보인다(390: 글자 913~1015, 띠 825~1002).

**지시**
```css
/* 기존 .word 규칙에서 bottom·font-size·line-height만 바꾼다 */
.hero{--wf:min(14.6vw,23svh)}
.word{bottom:84px;font-size:var(--wf);line-height:.74}
.copy{padding-bottom:calc(var(--wf) * .78 + 96px)}   /* 기존 88px 대체: 글자 자리만큼 카피를 위로 올린다 */

@media (max-width:860px){
  .copy{padding-bottom:0}                              /* 기존과 같음 */
  .word{position:relative;order:2;bottom:auto;font-size:14.6vw;line-height:.74;margin:44px 0 -.5em}
  .hero .joy{order:3;margin-top:0}                     /* 기존 order:2, margin 24px auto 0 → 위·아래만 바꾼다 */
}
```
- 14.6vw로 하면 "UNSILENT" 전체가 화면 폭 안에 들어온다(좌우 약 3% 여백). 23svh는 낮은 화면(1280×720)에서 글자가 CTA를 덮지 않게 하는 상한이다.
- `.copy` 아래 여백을 글자 높이에 묶었다. 어느 화면 높이에서도 버튼 아래부터 띠 위까지 글자 자리가 비어 있다.
- 모바일은 글자를 흐름 안으로 넣는다. 버튼 아래, 관객 누끼 바로 위에 두고 누끼의 들어 올린 팔이 글자 아래쪽을 덮는다(`z-index:-2` 유지). 띠(`.credits`)는 순서상 그 아래다.
- 기존 `.word{bottom:0;font-size:24vw}` 모바일 규칙은 지운다.
- 헤드셋 스위치 동작(UN 열림, 스트로크 색 전환)은 그대로 둔다.

## 3. 공연 방식 카드 "이 방식으로 문의 →" 버튼

**원인**: `.volc .ask-b`가 14px 라임 텍스트 링크이고 왼쪽에 붙어 있다. 사진 위 텍스트 덩어리의 마지막 줄처럼 보여 버튼으로 읽히지 않는다.

**지시** — 기존 `.volc .ask-b` 두 줄(207·208행)을 아래로 바꾼다.
```css
.volc .ask-b{all:unset;box-sizing:border-box;cursor:pointer;align-self:flex-end;margin-top:20px;display:inline-flex;align-items:center;justify-content:center;gap:8px;min-height:44px;padding:11px 20px;border-radius:99px;background:var(--lime);color:var(--ink);font-weight:800;font-size:15px;line-height:1.2;transition:transform .3s var(--ease),box-shadow .3s,background .3s,color .3s}
.volc .ask-b:hover{transform:translateY(-2px);box-shadow:0 12px 30px -12px rgba(194,234,140,.7)}
.volc .ask-b:focus-visible{outline:3px solid var(--lime);outline-offset:4px}
/* 장소를 고른 뒤: 고른 카드만 채운 라임, 나머지는 라임 외곽선 */
.vols.has .volc:not(.sel) .ask-b{background:rgba(17,28,28,.6);color:var(--lime);box-shadow:inset 0 0 0 1.5px var(--lime)}
@media (max-width:560px){.volc .ask-b{align-self:stretch}}
```
- 데스크톱과 태블릿(561~960, 카드 1열)에서는 오른쪽 아래에 붙인다. `.volc`가 `flex-direction:column`이라 `align-self:flex-end`로 충분하다.
- 560px 이하 모바일은 카드 폭 전체로 펼친다. 엄지로 누르기 쉽고, "오른쪽" 요구와도 어긋나지 않는다. 높이 44px 이상(터치 타깃)이다.
- 라임 절제: 처음 화면에는 라임 버튼이 3개 나란히 보인다. 장소를 고르면 고른 카드 하나만 채운 라임이 된다. 헤더 CTA와 같은 `.cta` 모양(알약형, ink 글자)이라 새 장식이 아니다.
- 대비: ink #1A2828 on lime #C2EA8C는 약 11:1, 외곽선 상태의 lime on 어두운 바탕은 4.5:1을 넘는다.
- reduced-motion에서는 전역 규칙으로 transition이 꺼진다. 추가 작업 없음.

## 4. DJ 패널 — 정보가 다 보이기 전에 다음 DJ가 덮음

**재현 (1440×900, 모션 켬, 스크롤 단계별)** — `cmp-dj-before.jpg`
- 각 `.djp`는 높이가 정확히 100svh(900)인 `position:sticky;top:0`이다. 텍스트 상자는 패널 아래쪽에 붙어 있다(버튼 줄 아래 끝 796px).
- 패널이 맨 위에 닿는 순간 다음 패널이 바로 아래에서 올라오기 시작한다. 버튼 줄은 다음 패널 윗변이 796px 위로 올라오면, 즉 **고정 후 104px 스크롤만에** 가려지기 시작한다.
- 들어올 때 버튼 줄이 화면에 다 들어오는 시점부터 계산해도, 이름부터 버튼까지 전부 보이는 구간은 **약 208px(마우스 휠 1~2칸)**뿐이다. 1280×720에서도 206px로 같다. 트랙패드로 한 번 밀면 그냥 지나간다.
- 등장 애니메이션(`.rv`)은 DJ 패널 안에 없다. 원인은 모션 타이밍이 아니라 **머무는 스크롤 구간이 없는 구조**다.

**지시** — 기존 225행 sticky 미디어쿼리 안에 추가한다.
```css
@media (min-width:861px) and (min-height:640px){
  .stack .djp{position:sticky;top:0;margin-bottom:70svh}   /* 고정된 채 70svh 동안 머문다 */
  .stack .djp:last-child{margin-bottom:0}
  .stack::after{content:"";display:block;height:70svh}       /* 마지막 KALI도 같은 시간 머문다 */
  .stack .djp+.djp{box-shadow:0 -40px 80px -20px rgba(0,0,0,.6)}  /* 기존 그대로 */
}
```
- 효과: 전부 보이는 구간이 208px에서 **약 838px**로 늘어난다(104 + 630 + 104, 1440×900 기준, 휠 7~8칸).
- 마지막 패널은 `margin-bottom`으로 하면 안 된다. 바깥 여백이 `.stack` 밖으로 빠져서 KALI 다음에 630px짜리 빈 화면이 생긴다(시험해서 확인). 그래서 `.stack::after` 스페이서를 쓴다. 이렇게 하면 KALI가 고정된 채 머문 뒤 `#rec`이 바로 이어 올라온다(`dj-after-last-to-rec.jpg`).
- 값 근거: 50svh는 트랙패드 한 번에 지나갈 수 있다. 100svh는 "멈춘 것 같다"는 느낌이 난다. 70svh를 기준으로 하고, 조정한다면 60~80svh 범위에서 바꾼다.
- **모바일(≤860 또는 높이 <640)**: 지금처럼 sticky 없이 세로로 이어 붙인다. 겹침이 없어서 정보가 가려지지 않는다(390: 패널 992~1028px, 사진 → 텍스트 → 버튼 순서). 변경 없음.
- **reduced-motion**: 스크롤에 직접 묶인 겹침이라 자동 재생 모션이 아니다. 같은 규칙을 그대로 쓴다. 등장 모션을 새로 넣지 않으므로 끌 것도 없다.
- 덧붙여, 패널 안에 등장 모션(텍스트 라이즈 등)을 새로 넣지 않기를 권한다. 넣으면 "다 나타나기 전에 넘어간다"가 다시 생긴다.

**비교 이미지**: `cmp-dj-before.jpg`(진입 / 고정 / +150 버튼 가려짐 / +450 / +750), `cmp-dj-after.jpg`(진입 / 고정 / +630 아직 전부 보임 / +930 덮기 시작 / +1260), `dj-after-last-to-rec.jpg`

## 5. 테크라이더 장비 카드 (HEADSET / DJ DECK / TRANSMITTER)

**원인**
- `.kit figure`가 `aspect-ratio:1` + `display:grid;place-items:center`이고, 이미지는 `max-height:76%`다. 그런데 부모 높이가 정해지지 않아서 %가 무시된다. 그래서 이미지 원래 비율대로 높이가 잡히고, `aspect-ratio`는 최소값처럼 동작해 카드가 늘어난다.
- 결과: 1440에서 카드 높이가 HEADSET 235 / DJ DECK 188 / TRANSMITTER 224px로 다르고, 라벨 위치도 209 / 162 / 198px로 다르다. 390에서도 135 / 111 / 129px로 다르다.

**지시** — 기존 `.kit figure`, `.kit img`, `.kit figcaption`(299~301행)을 아래로 바꾼다.
```css
.kit{display:grid;grid-template-columns:repeat(3,1fr);gap:10px;align-items:start}
.kit figure{position:relative;display:block;aspect-ratio:1;margin:0;padding:0;overflow:hidden;min-width:0;border-radius:16px;background:radial-gradient(circle at 50% 60%,var(--ink-3),var(--ink-2))}
.kit img{position:absolute;left:10%;top:8%;width:80%;height:64%;max-width:none;max-height:none;object-fit:contain;object-position:50% 50%;filter:drop-shadow(0 16px 24px rgba(0,0,0,.5))}
.kit figcaption{position:absolute;left:12px;bottom:12px;line-height:1;font-family:var(--f-mono);font-size:11px;letter-spacing:.1em;color:var(--mute)}
```
- 세 카드 모두 정사각형이고, 이미지 영역(위 8%~72%, 폭 80%)이 같다. 라벨은 아래 12px 기준선에 맞춘다.
- 측정(후): 1440 → 카드 188×188 ×3, 이미지 영역 위 15px·높이 120px 동일, 라벨 위치 동일. 390 → 111×111 ×3 동일.
- 라벨 10px → 11px: design.md "HUD·라벨 11~12px" 기준에 맞춘다. 390에서 "TRANSMITTER"(11자)가 카드 폭 111px 안에 들어간다. 다른 폭에서는 web이 확인한다.
- 대비: mute on ink-2(라벨이 놓이는 카드 모서리 쪽)는 5.1:1이다. 중앙 ink-3 위라면 4.3:1이지만 라벨은 모서리에 있다.
- 이미지 파일(eq_*.webp)은 그대로 쓴다. 투명 배경이고 여백 없이 잘려 있어 `object-fit:contain`으로 크기가 고르게 맞는다.
